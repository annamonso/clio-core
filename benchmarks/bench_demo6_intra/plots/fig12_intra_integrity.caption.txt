Framework capture integrity for the same intra-agent fan-out runs as Fig 11. Three checks per run: (1) the planner's main InteractionRecord contains exactly N entries in `response.tool_calls`; (2) every `tool_use.id` in that array is distinct; (3) all N tool_calls land in a single InteractionRecord (not split across LLM turns). All three checks pass on 100 % of runs at every N level (total n=9). The reformulated peer-bundle hazard from the morning's adapter bug — where N concurrent tools could in principle merge under shared session_id — does not manifest at this level: the framework's interaction model nests tool_calls inside a single record, so concurrency cannot trigger session-level aggregation.
